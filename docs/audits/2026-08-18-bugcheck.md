# Full audit — bugcheck, spec compliance, tech debt

**Date:** 2026-08-18 · **Branch:** `claude/bugcheck-spec-compliance-debt-rqb4as`

Method: five independent review passes (core service and domain; Cypher
repositories; BUILD_SPEC compliance end to end; adapter parity and Console;
tech debt and peripherals), every finding verified against the code before
being accepted, plus the full test matrix run against a live NornicDB built
from source (fast suites, persistence, e2e — all green before and after the
fixes below, except the 39 tests that were failing at baseline).

The safety core held up well under adversarial review: capabilities,
approval hash-binding and expiry, the outbox and idempotency, external
verification, the payee/payment gate, the task state machine, the section
36/39 vocabularies, MCP identity binding, secret-store cryptography, and
Cypher parameterisation were all checked and found faithful to BUILD_SPEC —
most of them test-pinned. What follows is what was *not* right.

---

## Fixed in this pass

Each of these is a commit on this branch; the messages carry the detail.

1. **The emergency stop never reached the running MCP server** *(critical)*.
   Safe mode was snapshotted at container construction and the Console toggle
   updated only the HTTP process; the MCP process — the surface Hermes acts
   through — kept the boot-time answer until restart. The config service and
   secret vault also cached their files forever, so provider disables and
   credential deletions had the same blind spot. All three now invalidate on
   file change, and `LifeOpsCore.safe_mode` reads a live source per
   capability check.
2. **A decision on an approval was not final** *(major)*. `decide()` accepted
   decisions on non-PENDING approvals: a second request within the TTL could
   flip DECLINED to APPROVED and resurrect a CANCELLED action to execution,
   or overwrite the record of an executed one. Now refused in the domain.
3. **`tests/spec` crashed on Python 3.11 (39 failures at baseline)** — it
   used `Protocol.__protocol_attrs__`, which exists only on 3.12+, while the
   project declares `>=3.11`. CI never ran `tests/spec` at all and ran mypy
   with `|| true`, so neither this nor the 20 standing mypy errors could
   gate. All fixed; mypy is now clean and both gates are real, in CI and in
   `make check`.
4. **Fake/NornicDB repository drift** — the failure mode the conformance
   suite exists for, found in behaviour rather than signatures: payee
   re-approval silently discarded on the real DB but not the fake (the audit
   line would name an approver the record contradicted); `Bill.update`
   succeeding on a missing bill and silently dropping four fields' edits;
   the fake world repository missing the entity-type guard; nondeterministic
   orderings without id tiebreaks; a stale `APPROVED` edge surviving an
   approver change.
5. **`validate_amount`**: `".50"` crashed with an unhandled 500 instead of a
   validation refusal, and non-ASCII digits survived normalisation — two
   spellings of one amount could produce two hashes, the exact instability
   the validated-string design exists to prevent.
6. **Log redaction** missed dicts inside lists and suffixed key names
   (`smtp_password`), both realistic shapes on the paths that feed it.
7. **MCP structured errors**: pydantic validation errors from inline draft
   construction escaped as unstructured protocol errors instead of the
   promised `{ok: false}` shape. The server docstring also claimed an
   `X-LifeOps-Client` header selects identity over HTTP; no such code exists
   (every transport serves the `--client` launch identity) — corrected.
8. **Outbox honesty**: a phone call recorded the internal idempotency key as
   its "external reference" when the provider returned none.
9. **Console**: RoutinesPage corrupted scheduled times by the UTC offset on
   every save; BillsPage displayed due dates a day early west of Greenwich;
   the Approvals screen swallowed decide failures silently (the
   payload-changed case its hash binding exists for); `add_payee` was
   missing from the ActionType union; the login flow could store the
   literal string `"undefined"` as a bearer token.
10. **Config validation**: NUMBER fields accepted NaN/inf; numeric provider
    settings treated a stored, schema-valid `0` as "unset".
11. **Documentation told falsehoods** — corrected rather than papered over:
    CLAUDE.md's "no tool spends write_world" and "shopping and payment held
    by nobody"; SECURITY.md's "no client holds an external-action
    capability", "there is no audit log yet", the stale capability table,
    and the claim that a missing HTTP identity resolves to the least
    privileged default (it resolves to the Console — now documented as the
    deliberate trade it is); MCP_API.md frozen at Phase 4 ("fourteen
    tools" — there are thirty-three); `changes/requests/README.md`
    describing a Markdown format the code never writes; CONFIGURATION.md's
    wrong fresh-state for local ASR/TTS; the root-level Phase-0 handoff
    (`kimi.md`) contradicting README, now archived under `docs/`.

## Open — needs a design decision (ordered by severity)

These are real defects verified in code, left unfixed because each changes
behaviour in ways the owner should choose deliberately.

1. **Payee approval is split-brained** *(major, money-adjacent)*.
   `record_payee` creates an ADD_PAYEE action + approval, but deciding that
   approval never marks the payee approved, and `approve_payee` (the Bills
   screen button) neither checks nor consumes it. Approving the ADD_PAYEE
   card leaves the payee unusable; approving on the Bills screen leaves the
   card pending forever. Worse: re-recording an existing payee swaps
   `secret_ref`/details immediately, before any decision, while the approval
   carries forward — `NOT_AUTHORISED_BY[ADD_PAYEE]` explicitly says changing
   an existing payee's details is not authorised, but the code performs it
   un-gated. Mitigated by FINANCIAL_PAYMENT being Console-only. The fix is
   one flow, not two: payee approval should be an effect of deciding the
   ADD_PAYEE approval, and `upsert_payee` on an approved payee with changed
   `secret_ref`/`provider_entity_id` should drop the approval pending
   re-decision.
2. **An approval that expires undecided deadlocks its intent** *(major)*.
   The action stays live in NEEDS_APPROVAL forever; no path requests a fresh
   approval for an existing action, and idempotency dedup pins any re-prepare
   of the same payload to the stuck action. Needs a "re-request approval"
   path (or expiry moving the action to a re-preparable state).
3. **A declined or failed grocery checkout wedges the ShoppingList in
   SUBMITTING** *(major)*. Every exposed operation refuses a SUBMITTING
   list; `shopping.mark_failed` exists but has no caller. Decline and
   execution-failure should return the list to CART_BUILT (or CART_FAILED).
4. **Verification re-checks hold expiry** *(major)*. An action executed
   before the hold TTL but verified after it writes VERIFIED, then
   `confirm_booking` raises — the appointment stays HELD forever while a
   real event sits on the calendar, and no path can complete the section
   101 flow. Verification proved the event exists; expiry belongs to
   execution, not verification.
5. **`begin_commit` consumes the approval before the commit persists, and
   `execute_action` catches too narrowly** *(major)*. A RepositoryError (or
   an unexpected exception) mid-execution leaves the action live in
   EXECUTING with a spent approval — unfinishable and uncommittable. Consume
   is correct-by-pessimism (never double-spend), but the failure path needs
   a recorded FAILED result for unexpected exceptions too.
6. **`MANAGE_CONFIGURATION` is enforced nowhere** *(major)*. The `/config/*`
   routes take no client identity and check no capability — `PUT
   /config/system` can flip safe mode off gated only by the optional bearer
   password. Now recorded in SECURITY.md; the fix is a capability check on
   the config routes.
7. **The Console cannot execute, verify, or even display actions** *(major,
   spec sections 60-63)*. `actionsApi` has list/get only, nothing calls
   them, and no screen exposes execute / verify-externally /
   confirm-booking. A human approves and then the approved action sits
   forever unless someone hand-crafts an HTTP call. MCP excludes these on
   purpose; the Console is where they must live.
8. **Expired-but-pending approvals still render as decidable** — related to
   (2): `list_pending` returns them, the Console shows Approve buttons that
   can only fail (now at least visibly, after this pass's fix).
9. **`update_payload` recomputes the payload hash but not the idempotency
   key** *(minor)* — after a substitution, a fresh prepare of the new
   payload no longer dedups against the live action.
10. **ElevenLabs/CalDAV providers leak an `httpx.AsyncClient` per call**
    *(resource leak)* — built per call, `aclose` has no caller. Needs
    per-call `finally: aclose()` or a cached client per config fingerprint.
11. **Email/calendar providers declare zero required fields**, so
    `{"enabled": true}` with nothing configured reaches state `configured`;
    requiredness is enforced ad hoc in the factories. Registry should
    declare it (this changes fresh-state labels, hence a decision).
12. **`create_task` honours `TaskDraft.state`** *(latent)* — no adapter
    exposes it today, but the domain guard its own comment promises does
    not exist; a caller could create a COMPLETED task that never traversed
    the machine.
13. **`search` is gated on READ_WORLD alone but returns preferences and
    tasks** *(latent)* — all current READ_WORLD holders also hold the read
    trio, but the gate is wrong by the codebase's own standard
    (`get_entity_detail` filters per capability).
14. **Appointment holds call the provider before domain validation**
    *(minor)* — an end≤start draft places a real external hold, then raises
    locally with nothing recorded to cancel it from; caller-supplied
    timestamps are also compared lexicographically without normalisation.
15. **`rotate_master_key` is dead code with a dangerous window** — no
    caller, and a crash mid-rotation (key deleted, vault emptied, plaintexts
    in memory only) loses every secret. Either wire it up with a
    write-new-then-swap sequence or remove it.
16. **`request_code_change` / self-configuration are unreachable by Hermes**
    *(spec sections 73-74, 100)* — the core methods exist and are correct,
    but no MCP tool or HTTP route exposes them, so Hermes's SELF_CONFIGURE
    is unspendable over MCP and Phase 11 is in practice Console-only. The
    write path is also CWD-relative (`changes/requests`), which under the
    systemd unit's `ReadOnlyPaths` would fail or land elsewhere.
17. **Console/Activity is blind to the MCP process** — the durable audit
    log exists and has an API, but the Activity screen reads only the HTTP
    process's in-memory buffer, so everything Hermes does is invisible
    there. (Recorded in SECURITY.md known gaps.)

## Open — spec gaps not in the documented-deviation lists

BUILD_SPEC requirements that are simply not built, discovered by reading the
spec end to end. None were recorded as deviations before this audit; they now
have this document.

- **Four Console screens are permanent placeholders** (sections 10, 18, 20,
  90, 110): Calendar ("arrives in phase 7"), Knowledge, Files, Hermes. The
  Definition of Done (section 110) names Knowledge/Files explicitly. Backend
  APIs for calendar exist; the screens were never built.
- **The Today screen is still Phase 0** (sections 11, 93): no approvals
  needing review, no waiting durations, no calendar events — all exist in
  the backend; its own footer still says they're coming.
- **The Voice Bridge was never built** (sections 32-33, 94): provider
  adapters exist, but there is no streaming ASR→Hermes→TTS pipeline, no
  barge-in, no endpointing, none of section 33's latency instrumentation.
  Section 103's voice acceptance steps 8-15 cannot run.
- **None of section 75's eight Hermes skills exist** — `hermes/skills/`
  holds only a README saying they arrive with Phases 1-2.
- **Universal search covers 3 of ~12 domains** (section 19): people,
  preferences, tasks, by substring — no providers, assets, appointments,
  bills, documents, memory in the universal path, no hybrid retrieval.
- **Bills are unreadable over MCP** (section 50): the recorded rationale for
  Console-only payments says "Hermes can read what is owed", but no MCP
  tool or resource serves bills. Also absent from section 50's read list:
  `get_task`, `list_waiting_items`, asset/appointment reads (partly covered
  by resources).
- **Entity inspector** (section 16) lacks the waiting-items and documents
  panels; **no MFA routing** (section 66, moot until a real browser
  provider); **no first-run wizard** (section 23); **no chaos suite**
  (section 86, partially covered elsewhere); `VOICE.md` and
  `DISASTER_RECOVERY.md` from the spec's layout don't exist.
- **Section 35 capability-matrix deltas** beyond the recorded
  FINANCIAL_PAYMENT judgement: the interactive client is narrower than the
  (explicitly "Example") table. Defensible; now recorded here.

## Debt worth knowing about (no action forced)

- `configApi.discover` is dead code: the server's dynamic-options flow (the
  "Refresh voices" path) is unreachable from the Console, so the ElevenLabs
  voice/model selects only ever show static options.
- Stale phase copy across the Console (Today/Activity footers,
  `PENDING_ROUTES` labels) — misleading now that the phases shipped.
- Silent mutations without `onError` remain on Bills (approve payee), Tasks
  (create), Waiting (follow-up/resolve), Routines (delete — also
  unconfirmed), World (expand), Configuration (test). Approvals was fixed
  in this pass as the highest-stakes one.
- `_detect_runtime` is byte-identical in `voice/local.py` and
  `browser/real.py`; ElevenLabs lets httpx transport errors escape
  unwrapped where CalDAV wraps them in ProviderError.
- The Test button records `healthy=False` against unconfigured providers,
  and that stale verdict outranks a later valid configuration until re-test.
- `FakeTelephonyProvider.hangup` deletes the call record, contradicting the
  protocol's "independent confirmation of what a past call did";
  `FakeBrowser.build_cart` ignores `substitution_allowed`.
- The Console password is stored reversibly in the vault (compared
  plaintext) rather than hashed — inside the stated threat model, but worth
  a deliberate look.
- `docs/superpowers/` planning docs carry stale status headers; harmless as
  history.
- CI pins Python 3.12 only while the project claims `>=3.11`; a 3.11 matrix
  entry would have caught the conformance-suite crash. (The suite itself is
  now version-portable.)
