# Full audit — bugcheck, spec compliance, tech debt

**Date:** 2026-08-18 · **Branch:** `claude/bugcheck-spec-compliance-debt-rqb4as`

Method: five independent review passes (core service and domain; Cypher
repositories; BUILD_SPEC compliance end to end; adapter parity and Console;
tech debt and peripherals), every finding verified against the code before
being accepted, plus the full test matrix run against a live NornicDB built
from source (fast suites, persistence, e2e — all green before and after the
fixes below, except the 39 tests that were failing at baseline).

The safety core held up well under adversarial review: capabilities,
approval hash-binding and expiry, the outbox and idempotency, external
verification, the payee/payment gate, the task state machine, the section
36/39 vocabularies, MCP identity binding, secret-store cryptography, and
Cypher parameterisation were all checked and found faithful to BUILD_SPEC —
most of them test-pinned. What follows is what was *not* right.

---

## Fixed in this pass

Each of these is a commit on this branch; the messages carry the detail.

1. **The emergency stop never reached the running MCP server** *(critical)*.
   Safe mode was snapshotted at container construction and the Console toggle
   updated only the HTTP process; the MCP process — the surface Hermes acts
   through — kept the boot-time answer until restart. The config service and
   secret vault also cached their files forever, so provider disables and
   credential deletions had the same blind spot. All three now invalidate on
   file change, and `LifeOpsCore.safe_mode` reads a live source per
   capability check.
2. **A decision on an approval was not final** *(major)*. `decide()` accepted
   decisions on non-PENDING approvals: a second request within the TTL could
   flip DECLINED to APPROVED and resurrect a CANCELLED action to execution,
   or overwrite the record of an executed one. Now refused in the domain.
3. **`tests/spec` crashed on Python 3.11 (39 failures at baseline)** — it
   used `Protocol.__protocol_attrs__`, which exists only on 3.12+, while the
   project declares `>=3.11`. CI never ran `tests/spec` at all and ran mypy
   with `|| true`, so neither this nor the 20 standing mypy errors could
   gate. All fixed; mypy is now clean and both gates are real, in CI and in
   `make check`.
4. **Fake/NornicDB repository drift** — the failure mode the conformance
   suite exists for, found in behaviour rather than signatures: payee
   re-approval silently discarded on the real DB but not the fake (the audit
   line would name an approver the record contradicted); `Bill.update`
   succeeding on a missing bill and silently dropping four fields' edits;
   the fake world repository missing the entity-type guard; nondeterministic
   orderings without id tiebreaks; a stale `APPROVED` edge surviving an
   approver change.
5. **`validate_amount`**: `".50"` crashed with an unhandled 500 instead of a
   validation refusal, and non-ASCII digits survived normalisation — two
   spellings of one amount could produce two hashes, the exact instability
   the validated-string design exists to prevent.
6. **Log redaction** missed dicts inside lists and suffixed key names
   (`smtp_password`), both realistic shapes on the paths that feed it.
7. **MCP structured errors**: pydantic validation errors from inline draft
   construction escaped as unstructured protocol errors instead of the
   promised `{ok: false}` shape. The server docstring also claimed an
   `X-LifeOps-Client` header selects identity over HTTP; no such code exists
   (every transport serves the `--client` launch identity) — corrected.
8. **Outbox honesty**: a phone call recorded the internal idempotency key as
   its "external reference" when the provider returned none.
9. **Console**: RoutinesPage corrupted scheduled times by the UTC offset on
   every save; BillsPage displayed due dates a day early west of Greenwich;
   the Approvals screen swallowed decide failures silently (the
   payload-changed case its hash binding exists for); `add_payee` was
   missing from the ActionType union; the login flow could store the
   literal string `"undefined"` as a bearer token.
10. **Config validation**: NUMBER fields accepted NaN/inf; numeric provider
    settings treated a stored, schema-valid `0` as "unset".
11. **Documentation told falsehoods** — corrected rather than papered over:
    CLAUDE.md's "no tool spends write_world" and "shopping and payment held
    by nobody"; SECURITY.md's "no client holds an external-action
    capability", "there is no audit log yet", the stale capability table,
    and the claim that a missing HTTP identity resolves to the least
    privileged default (it resolves to the Console — now documented as the
    deliberate trade it is); MCP_API.md frozen at Phase 4 ("fourteen
    tools" — there are thirty-three); `changes/requests/README.md`
    describing a Markdown format the code never writes; CONFIGURATION.md's
    wrong fresh-state for local ASR/TTS; the root-level Phase-0 handoff
    (`kimi.md`) contradicting README, now archived under `docs/`.

## Resolved in the follow-up pass (same branch, 2026-08-18)

Every design-decision bug below was fixed after this audit was first
written; the decisions taken are recorded with each commit. What follows is
the updated disposition of the original seventeen findings.

1. **Payee approval split-brain** — *fixed.* Deciding the ADD_PAYEE card
   marks the payee payable and closes the outbox record; the Bills screen's
   button routes through the pending card; re-recording an approved payee
   with changed payment details revokes the approval first (a deliberate
   `clear_payee_approval` repository operation).
2. **Expired-approval deadlock** — *fixed.* A late decision marks the card
   EXPIRED and issues a fresh PENDING one; the human still decides, and a
   stale card self-heals on click instead of dead-ending the intent.
3. **Shopping SUBMITTING wedge** — *fixed.* Declined and failed checkouts
   both return the list to CART_BUILT; a retried checkout produces a fresh
   decidable card.
4. **Verify-after-hold-expiry** — *fixed.* Expiry gates execution only;
   a verified booking is recorded even when verification lands after the
   hold TTL.
5. **Consume-before-commit / narrow catches** — *fixed for the failure
   record*: execute_action now catches every LifeOps error plus pydantic
   validation errors and records FAILED. (Consuming the approval before the
   external call stands — never double-spending an approval is the right
   pessimism; the un-recorded failure was the bug.)
6. **MANAGE_CONFIGURATION unenforced** — *fixed.* All /config and /voice
   management routes require the capability (checked in the adapter, since
   the config surface deliberately bypasses core; safe_mode exempt so the
   stop cannot lock its own switch).
7. **Console cannot execute/verify** — *fixed.* A new Actions screen runs
   approved actions and verifies executed ones; the approve → execute →
   verify chain is now walkable end to end in the product.
8. **Expired-but-pending cards render decidable** — *mitigated by (2)*:
   clicking one now reissues a fresh card instead of failing silently
   (and the Approvals screen surfaces failures since the first pass).
9. **update_payload idempotency key** — *fixed*; recomputed with the hash.
10. **httpx client leaks** — *fixed*; per-call providers are closed in
    finally (streams after exhaustion), and ElevenLabs wraps transport
    errors as ProviderError.
11. **Email/calendar required fields** — *fixed*; declared in the registry,
    so enabled-but-empty reads NOT_CONFIGURED. Deviates from section 104's
    fresh-state labels the same way Telegram already did (recorded in
    tests/unit/test_configuration.py). Updating a provider's config also
    clears its stale health verdict.
12. **TaskDraft.state honoured** — *fixed*; create_task refuses non-CAPTURED.
13. **search over-serves READ_WORLD** — *fixed*; per-section capability
    filtering.
14. **Holds validate after the provider call** — *fixed* (window validated
    first). Caller-supplied timestamp normalisation remains open, below.
15. **rotate_master_key** — *fixed*; rotation now writes new-key → new-vault
    (which names its key file) → remove old key, so every crash window
    leaves a consistent pair; tested for both windows.
16. **request_code_change unexposed** — *fixed*; it is an MCP tool, and the
    write path resolves to an absolute directory instead of the CWD.
17. **Activity blind to the MCP process** — *fixed*; the screen shows the
    durable audit log (which records every surface) alongside the live
    process feed, each labelled for what it covers.

## Still open — real work, deliberately not rushed

- **Caller-supplied timestamps are compared lexicographically** with no
  format/UTC normalisation (holds, calendar ranges): "…T10:00:00+02:00"
  vs "…Z" comparisons are meaningless. Needs a normalisation pass at the
  domain boundary.
- **The Console password is stored reversibly** in the vault (compared
  plaintext) rather than hashed. Inside the stated master-key threat
  model, but hashing it costs little.
- **Expired approvals still appear in list_pending** until clicked; a
  repository-level filter plus a Console "expired — reissue" affordance
  would be cleaner than the current self-heal-on-click.

## Open — spec gaps not in the documented-deviation lists

BUILD_SPEC requirements that are simply not built, discovered by reading the
spec end to end. None were recorded as deviations before this audit; they now
have this document.

- **Four Console screens are permanent placeholders** (sections 10, 18, 20,
  90, 110): Calendar ("arrives in phase 7"), Knowledge, Files, Hermes. The
  Definition of Done (section 110) names Knowledge/Files explicitly. Backend
  APIs for calendar exist; the screens were never built.
- **The Today screen is still Phase 0** (sections 11, 93): no approvals
  needing review, no waiting durations, no calendar events — all exist in
  the backend; its own footer still says they're coming.
- **The Voice Bridge was never built** (sections 32-33, 94): provider
  adapters exist, but there is no streaming ASR→Hermes→TTS pipeline, no
  barge-in, no endpointing, none of section 33's latency instrumentation.
  Section 103's voice acceptance steps 8-15 cannot run.
- **None of section 75's eight Hermes skills exist** — `hermes/skills/`
  holds only a README saying they arrive with Phases 1-2.
- **Universal search covers 3 of ~12 domains** (section 19): people,
  preferences, tasks, by substring — no providers, assets, appointments,
  bills, documents, memory in the universal path, no hybrid retrieval.
- **Bills are unreadable over MCP** (section 50): the recorded rationale for
  Console-only payments says "Hermes can read what is owed", but no MCP
  tool or resource serves bills. Also absent from section 50's read list:
  `get_task`, `list_waiting_items`, asset/appointment reads (partly covered
  by resources).
- **Entity inspector** (section 16) lacks the waiting-items and documents
  panels; **no MFA routing** (section 66, moot until a real browser
  provider); **no first-run wizard** (section 23); **no chaos suite**
  (section 86, partially covered elsewhere); `VOICE.md` and
  `DISASTER_RECOVERY.md` from the spec's layout don't exist.
- **Section 35 capability-matrix deltas** beyond the recorded
  FINANCIAL_PAYMENT judgement: the interactive client is narrower than the
  (explicitly "Example") table. Defensible; now recorded here.
